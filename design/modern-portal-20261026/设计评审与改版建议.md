# TexoPub 设计评审与改版建议

日期：2026-10-26。范围：平台首页、发布页和个人空间的设计方向；交付为评审与本地首页提案。线上首页、发布页已用原生 Chrome 直接查看，个人空间只评阅模板源码，未完成其视觉/交互评审。没有部署生产站、调整正式作品或改变展示范围。

用户本轮明确选择：**鲜明创意社区：颜色与构图更大胆**。这条新选择优先于此前“百科/旧式网址导航”的视觉倾向。品牌名称与 T 标志继续使用；新增点缀色、排版及构图为本地提案，不能视为已批准上线。

## 结论：功能已经是产品，展示仍像目录页

原站有真实分类、搜索、空间、发布和管理流程，问题集中在作品发现体验及整体视觉表达。现状让访客先看到“这个站怎么分类”，随后才看到“这里有什么值得打开”。对于只含三份公开作品的当前阶段，组织体系的存在感超过了内容。

AI 模板感判断：有。主要表现是默认密度的标题/说明/输入框/细线列表组合，模块几乎都使用相近的视觉重量，缺少属于 TexoPub 的构图。没有发现全站滥用蓝紫渐变、发光背景或玻璃效果；不应为了“现代”补上这些套路。

## 证据与优先问题

| 优先级 | 实际问题 | 影响 | 改法 / 对应 skill |
|---|---|---|---|
| P1 | 首页源码有 37 个分类按钮，公开目录只有 3 份作品；侧栏展示大量零数量分类 | 内容少的阶段，页面显得空、长且欠维护；访客先筛选再认识作品 | 首页优先展示有内容的主题；完整分类在独立展开区保留，正式分类体系不变。`layout`、`distill` |
| P1 | 三份作品中两份 catalog.cover 为空；有封面的苏博也只是列表右侧小图 | 网页作品的价值只能靠读摘要理解，缺少打开欲望 | 使用真实页面截图或专属编辑封面；作品主图比专属小图标更有分量。封面缺失时提供经过设计的文字封面。`bolder`、`layout` |
| P1 | 品牌朱橙主要用于链接和按钮，内容区主要是米色背景、文字与细线 | T 标志与整体页面没有形成统一视觉记忆 | 用朱橙建立一处明确主视觉，青柠作少量对比，墨色支撑导航与文字；以交织 T 的构成为品牌细节。`bolder`、`colorize` |
| P1 | 发布页同时给出 ChatGPT 插件、Skill/命令行、密钥说明，后续仍统一强调“先给 AI 密钥” | 连接插件的用户可能以为还必须去创建密钥；第一个行动被长说明挤到后面 | 先选择“ChatGPT 插件 / 本地 AI Agent”，对应显示连接或凭证步骤，然后提供复制操作。维持现有 AI 发布模式。`clarify`、`layout` |
| P2 | 首页、发布页、空间通过不同 CSS 片段演进，控件、间距与说明样式不完整统一 | 感觉像陆续补齐的页面集合 | 提取平台颜色、字号、间距、按钮、输入、导航、状态与作品展示组件；个人空间使用适合管理的信息密度。`typeset`、`polish` |

### 当前设计健康分（暂定）

这是基于已查看页面和源码的设计评估，不是用户测试、性能测试或无障碍认证；未执行写入、登录、删除等操作。

| Nielsen 启发式 | 分数 / 4 | 依据 / 主要问题 |
|---|---:|---|
| 系统状态可见 | 3 | 搜索结果与空间有状态文本；目录加载时的零数量与真正空内容仍容易混淆 |
| 符合现实语言 | 3 | 作品介绍自然；发布页同时出现插件、Skill、凭证等多条概念路径 |
| 用户控制 | 3 | 有清除筛选、导航和取消入口；本轮未实测管理写入 |
| 一致性 | 2 | 品牌统一，具体页面的控件与布局仍有拼接感 |
| 错误预防 | 3 | 源码包含展示说明和删除确认；本轮未重测删除 |
| 识别胜于回忆 | 2 | 文字标签明确，作品预览不足，发布需记住跨页步骤 |
| 灵活高效 | 2 | 有搜索、形式和分类过滤；没有搜索键盘快捷入口 |
| 美观与简约 | 1 | 组织体系压过三份真实内容；缺少视觉主次和作品展示 |
| 错误恢复 | 2 | 有清除、无结果提示；目录加载失败主要让用户刷新 |
| 帮助与说明 | 3 | 说明丰富，分流和呈现时机有待改善 |
| 合计 | **24 / 40** | 可用基础已有，展示和首次发布引导优先改 |

认知负荷八项检查：单一焦点、信息分块、视觉层级、选择精简、渐进展开存在问题；相关元素分组、基本任务连续性、跨屏记忆负担（首页）基本通过。按该 skill 的检查方法为 **5 / 8 项待改**。37 是整个分类树的按钮总数，不能写成首屏同时可见 37 项；实际可见数取决于视口。不能把“四个选项”当成任何网站都不可超过的硬规则，这里的问题是多数选项没有内容。

## 自动检测与误报

按 `critique` 要求安排独立子代理做确定性检测；主评审负责源码和视觉。使用 `impeccable@4.7.0`，新版命令为 `npx impeccable detect --json`；Skill 中的旧命令已不适用。

- HTML 扫描两条：主页米色背景、标题区 padding。
- CSS 补扫一条：`templates/space.css:1` 的 `.space-note` 使用 3px 左侧色条，不符合本套 skill 的装饰规则。
- 米色属于现有批准品牌，不能简单视为错误；新方向主要改变颜色的视觉占比。
- padding 告警没有正确理解 `.results-heading` 覆盖与手机移除上边框，实看未见标题贴线，按误报处理。
- space/publish 是 HTML 片段，零发现不意味着它们的实际页面合格。
- 浏览器扩展控制超时后已改用原生 Chrome 视觉核对；没有注入检测覆盖层，不声称提供了在线覆盖层。

完整检测结果位于 `../../evidence/design-review-20261026/detector-summary.json` 及同目录原始 JSON。

## 值得保留

1. 名称、T 符号与朱橙已有识别基础，继续把它们做深。
2. 三份作品都是真实、可访问、说明具体的成果，适合精心展示；不需要填假内容。
3. 分类、搜索、焦点样式、状态提示已有可用基础，改版不必推倒功能层。

## 用户视角检查

- 首次访客：标题说明网站用途，但先面对长分类树，无法快速从封面理解哪份作品有用。提案改为先见作品，再按当前主题筛选。
- 创作者：点击“发布”后看到多条接入路径和统一密钥说明。需要明确“我用的是哪个 AI”，随后才提供对应下一步。
- 键盘/辅助技术用户：现有焦点和语义状态值得保留；37 个分类入口会增加 Tab 遍历负担。本地提案提供搜索 `/` 快捷键、语义筛选状态、无结果恢复；没有做完整读屏测试。

## 选定方向：鲜明创意社区

品牌表达：**有主张、爱创造、愿意分享**。社区气质先从作品、作者和共创过程建立。现阶段不补点赞、关注、排名或动态流等产品功能。

- 色彩：朱橙作为主视觉，青柠用于重点文字、设计封面和发布提示区，墨绿/墨色支撑正文；浅色内容区为阅读留空间。
- 字体：保留已有 Manrope 与中文正文字体，扩大标题与辅助文字的尺度差。无需为了不同而更换品牌字标。
- 构图：一份大幅作品 + 两份较小作品，图片、编辑封面、标本档案图形成节奏。三份作品都使用现有公开资料；书籍封面是本地新排版示意，不冒充原网页截图。
- 首页导航：发现 / 我的 / 让 AI 发布。完整二级分类保留为正式改版阶段的可展开导航；本次概念只实现三项当前内容筛选。
- 动效：作品封面轻微缩放、控件状态反馈；减少动态偏好时关闭过渡。更复杂动效放在布局确认之后。
- 手机：重新安排标题、搜索和作品次序，保持搜索、筛选、作品与发布入口；不把桌面长侧栏挤成横向目录。

### 全站页面如何统一

| 页面 | 新的设计重点 |
|---|---|
| 发现首页 | 视觉封面、当前主题、作者及作品用途；搜索随时可用 |
| 我的空间 | 同一品牌导航与控件，作品管理采用清楚紧凑的网格/列表；展示设置靠近对应作品，永久删除放在次级操作并保留确认 |
| 发布页 | 先选 AI 使用方式，再给对应连接/复制步骤；核心操作进入首屏，详细说明按需展开 |
| 个人公开主页 | 作者身份、简介与公开作品组成画廊；仅展示既有授权范围 |
| 平台作品查看器 | 品牌入口轻量，阅读空间交给作品；具体作品保持自己的设计 |

## 交付与验证

- `index.html` + `bold.css`：按用户选择制作的鲜明创意社区方向。
- `quiet.html`：最初较克制方向，仅供对照。
- `mobile.html`：390px iframe 中的真实响应式布局预览，非手机真机测试。
- 桌面 Chrome 已确认：三份公开作品显示，文学筛选变为一份；搜索无结果为零份且显示恢复按钮；点击恢复后三份重现。
- 390px 布局已直接查看：标题、搜索、筛选与第一份作品正常呈现；未做全尺寸设备矩阵检查。
- 截图在 `../../evidence/design-review-20261026/`。本地 HTTP 预览仅绑定 127.0.0.1:8768。
- 这是一份可操作的设计提案，不是全站改版交付；不修改生产模板、后台能力、正式作品或线上配置。

## 建议实施顺序

1. `bolder` + `layout`：以本地提案明确首页构图，建立封面资产规范；把完整分类折叠导航和实时目录接回正式首页。
2. `typeset` + `colorize`：整理全站 tokens 和组件，校验小字对比度与长标题状态。
3. `clarify`：发布页按 ChatGPT / 本地 Agent 分流；展示范围及素材权限继续采用现有真实语义。
4. `adapt`：个人空间、公开主页及手机布局一并适配；查看器与作品正文保持边界。
5. `animate`：仅增加有助于状态和操作反馈的动效，遵守减少动态偏好。
6. `polish`：最后统一控件、图标、焦点、加载/无结果/错误、封面缺失和长内容状态。

这一步之后最值得审的决策是：朱橙与青柠的配色强度、主视觉高度，以及作品封面能否让人产生打开欲望。方向已由用户明确，不需要再次询问泛泛的“想现代还是想活泼”。
