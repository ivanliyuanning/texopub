# 专辑与音视频收录：首期需求方案

日期：2026-11-02（Asia/Shanghai）

状态：用户已确认本方案并授权完整交互预览，明确「挥动网球测试」先不显示在个人主页。完整本地预览已完成并验证，说明与入口见 `next/albums-media/README.md`；功能分支 `codex/albums-media-preview`。音视频同时支持「上传文件＋外部链接」的需求已确认。生产接入、迁移、工具升级与上线尚未执行，本轮不上传网球内容。

## 1. 功能目标与实际样例

创作者通过 AI 把相关网页、视频、音频整理成一个有封面、固定网址和顺序的专辑，读者拿到一个链接即可浏览。专辑归类服务于个人项目组织，与平台既有二级分类并存。同一内容可以加入多个专辑，不复制正文、媒体或历史版本。

首个样例「挥动网球测试」：把已指定的网球位置与击球声试标网页发布为 unlisted，再加入同名专辑。网页不在个人主页独立作品区、发现或公开素材目录中出现；同事通过专辑进入网页并查看、播放。当前仅授权这份标注网页的分享，不自动纳入竞品研究、旧模型评测、完整原片或其他测试报告。

成功标准是同事在未登录、没有原本机文件的电脑或手机上，能打开专辑、找到标注页、观看两个片段、定位声音节点并放大图片；更新后仍使用原链接。

## 2. 专辑规则

- 专辑拥有独立身份、标题、可选简介、封面、稳定网址、创建/更新时间和内容顺序；改标题不改地址，更新不另建副本。
- 首期展示位置为「不展示 / 仅个人主页」，默认不展示；两者都可凭链接匿名访问。不把本次需求扩大为全站专辑发现、成员权限或企业空间。
- 专辑展示和成员内容原有 listing 独立。加入专辑不改成员 listing；专辑显示到主页时，其 unlisted 成员仍不进入独立作品区，但访客可以经该专辑找到并打开它们。
- 把指定内容加入专辑，是允许该内容出现在专辑目录的明确操作。AI 不自动扫描、收齐或加入其他 unlisted 内容。用户已经指定专辑和成员时直接执行；跨出该范围才询问。
- 「不展示」只表示没有公开目录入口，并非同事专属或密码保护；任何拿到链接的人都能访问，也可能转发。首期不实现密码、成员白名单、链接失效期或 DRM。
- 个人主页关闭时，专辑直链仍可访问，但不显示主页入口；AI 不代开个人主页。
- 每份内容在同一专辑只出现一次；支持加入、移出、调整顺序，一份内容可属于多个专辑。首期只添加本人作品/素材；第三方内容先按外链收录规则创建记录。
- 默认跟随成员当前已发布版本。移出内容或删除专辑，不删除成员及媒体文件。成员归档、删除或发布状态变化后不能通过专辑绕过生命周期检查。
- 首期不做嵌套专辑、共同编辑、评论、点赞或版本快照；不要把专辑做成新的文件复制系统。

## 3. 页面与交互

沿用用户已认可的共创画廊方向：亲切、清楚、有活力，使用已有品牌和字体、真实封面和明确内容类型；不为这次功能另改全站视觉。手机、键盘浏览、减少动态效果偏好均保持可用。

### 个人主页

作者介绍与 AI 伙伴 → 专辑区域 → 共创作品 → 素材。专辑是内容区顶部，不盖过作者身份；没有可展示专辑就隐藏整个区域。专辑卡片展示封面、标题、可选短简介、可访问内容数，可按用户指定顺序排列。数量较多时显示一部分并提供「查看全部」，不默认轮播或自动滑动。

专辑中的内容若自身为 profile/public，仍按原规则出现在独立作品/素材区，避免加入专辑导致原入口消失。专辑为 unlisted 时，不从其他公开作品的「所属专辑」、站内搜索、公开 API 列表或站点地图反向暴露专辑名称、成员关系和地址。

### 专辑详情

封面、标题、简介、创作者与目录为主；下方按用户排序混排网页、视频、音频，明确类型、时长（确知时）和来源。支持专辑内标题搜索及类型筛选。网页打开现有阅读入口；音视频进入播放页，提供返回专辑的上下文。外部平台页面明确显示来源和「前往原站播放」，不伪装托管或已验证可嵌入。

不自动播放音视频；可见的播放、暂停、音量、进度、倍速和视频全屏操作优先使用可靠原生能力。字幕存在时可开关；无字幕/转写则不显示空入口，不自动调用模型生成转写。未经授权不自动批量播放、下载或分析媒体。

### 本人空间与管理

增加「专辑」列表及概览入口，可见展示范围、成员数、封面和状态。创建、改名、简介、封面、成员与排序仍交给 AI，网站保留当前页一句说明和普通接入说明链接；不新增手工上传/编辑表单、卡片管理按钮、复制按钮或提示词弹窗。

### 状态与文案

| 状态 | 读者/作者看到什么 |
| --- | --- |
| 公开可访问且有内容 | 按顺序显示可用内容；计数与实际可访问项一致 |
| 专辑空 | 「专辑还没有内容。」本人空间另说明可让 AI 加入内容 |
| 搜索无匹配 | 「没有找到匹配的内容。」可清除筛选 |
| 正在加载 | 复用已有共创加载态，不伪造进度或时长 |
| 暂时读取失败 | 显示可重试的错误，不把失败当空专辑 |
| 成员被归档/删除 | 普通读者只见「内容暂不可用」或隐藏占位，不泄露旧摘要/封面/原地址；作者可见具体状态并整理 |
| 专辑已归档/删除 | 直链不可访问；成员原地址与展示范围保持 |
| 音视频不兼容/外链失效 | 明确无法播放的原因范围；有原文件时提供原文件入口，外链可前往原站 |
| 内容不足或无封面 | 稳定封面兜底，不虚构热度、时长、简介或素材 |

首期不提供匿名反馈写入。JSON 导出属于原标注网页已有功能，不等于新增在线标注、共享保存或同事协作审校。

## 4. 音视频收录

用户已选择同时支持下列方式：

1. 上传文件：保留原始字节、校验值和稳定资源地址，网页和专辑均可引用；播放器属于资源展示能力，不要求为每段视频手工制作网页。
2. 外部直链：记录公开 HTTPS 地址和来源，支持时直接播放；不自动复制至 TexoPub，不保证外站链接永久可用，也不把存在 URL 当作已通过播放验证。
3. 平台页面链接：作为外部音视频条目收录，首期跳转原站播放；嵌入需按平台能力另行适配，不承诺所有平台链接都能在站内播放。

媒资记录至少包含类型、标题、可选说明、来源/托管方式、资源地址、封面/音频封面、大小（托管文件必需）、MIME、校验值（托管文件必需）、时长/宽高/编码（实际探测取得）、listing、版本与状态。音频无封面可生成标题排版；视频可从真实画面选帧，避免把 AI 生成画面冒充片中镜头。已有素材按 MIME 自动识别，不复制成第二份记录。

上传前区分容器与实际编码，实际浏览器播放失败不得仅凭扩展名声称支持。源格式不能直接播放时保留原件；需要转码再明确产出播放副本和额外存储，未经授权不有损转换或降低画质来凑限额。不把 NAS 媒体或整段私人原片纳入本次素材范围。

大文件上传需要独立的可恢复分块链路、校验、进度、失败续传、草稿过期与孤立分块清理，不能只提高网页上传限额。建议首期托管音视频单文件上限可配置，初始候选 256 MiB，仍受账号剩余额度约束；最终上限需结合现有服务链路的实际验证确定，不在实现前声称已支持。现有网页单文件 25 MiB、总包 100 MiB 的行为应保持兼容。

播放验收需覆盖 GET/HEAD、正常及越界 Range、尾部范围请求、断点拖动、暂停后恢复、跨域媒体读取与缓存/下架行为。页面默认不预下载整段内容；封面和元数据轻量加载。

托管文件按真实存储对象及保留的版本计额度：加入多个专辑不重复计费；封面和播放副本按实际存储计入，外链记录不虚报外站视频字节为本机用量。删除前展示被网页/专辑引用关系；清理对象需保护共用依赖。

## 5. 专辑封面与 Skill

建议对外规范：16:9，推荐 1600×900，最低 800×450；用户上传 JPG/PNG/WebP，建议 ≤5 MiB。其他比例允许由 AI 制作独立裁剪副本，不能拉伸或覆盖原件；标题、人物和标识尽量留在中间 80% 安全区，避免卡片或分享预览裁掉关键信息。此为新增方案，当前 API 尚未校验这些尺寸。

没有封面时由 AI 根据标题、主题生成专属封面并随专辑保存；可以采用品牌化 SVG/程序排版，无需每次调用付费生图。运行时保留稳定兜底，生成失败不阻断建立专辑。用户后来换封面后同步更新主页卡片、专辑页与分享预览。分享图可从封面生成适配副本，不要求用户另外准备一张。

Skill 需要同步说明：

- 创建/更新/删除专辑，查找本人专辑，加入/移出/排序，查看引用关系与稳定网址。
- 专辑及内容分别确定展示位置，已有明确选择不重复问，更新省略沿用；「不展示也可经专辑链接访问」必须说明清楚。
- 用户给出封面时检查真实格式/尺寸/大小与裁剪，无封面主动生成，不把封面收集反交用户。
- 上传文件、外链直连和平台跳转的区别、容量限制、编码探测、原件保留、上传续传与播放验证。
- 创建后独立读取专辑、成员关系、各自 listing、主页及公开目录，实开匿名分享地址；失败或仅部分上传不可宣称发布完成。
- 管理权限、当前版本/修订号、幂等重试和冲突处理继续沿用现有机制；不能靠换 ID 或 slug 绕过冲突。

CLI、REST、MCP、双语公共/本机 Skill、插件包、接入说明和版本号需同时覆盖。工具元数据变化必须刷新既有连接，并在新对话实际调用新增/受影响工具验收，不能以压 ZIP 或本机安装替代。

## 7. 实施顺序与验收

1. 确定本方案首期范围，建立功能分支，保留当前未提交宣传资料与任务状态。
2. 实现专辑身份、成员与独立展示规则；制作个人主页、专辑页、本人空间的完整可交互预览。
3. 打通音视频资源条目/播放器、外链收录与可恢复上传；确定实际文件上限。
4. 实现封面、分享预览、CLI/MCP/Skill 和文档；完成隔离服务验证和桌面/窄屏真实播放验证。
5. 用户认可预览与上线范围后，迁移/部署并独立核查；所有测试内容及历史版本永久清理，核对额度和旧链接。
6. 用已指定的标注网页作为正式首例：发布为 unlisted，建立 unlisted「挥动网球测试」专辑并加入该网页；不擅自加入其他网球资料。匿名完整验收后交付服务实际返回的专辑地址。

关键验收矩阵：专辑不展示/主页展示 × 成员 unlisted/profile/public × 主页开/关；确认只出现约定入口、不扩大公开目录、不泄露未收录内容。另验证重复加入、多个专辑共用、重排、旧修订冲突、换封面、成员归档/删除、删除专辑保留成员、草稿中断与续传、正常/失效外链、同一文件多处引用不重复占额。

实施参考：`.impeccable.md`；`impeccable/reference/spatial-design.md`、`responsive-design.md`、`interaction-design.md`。首期不需要另行选字体、重画品牌或增加社交系统。
