# 专辑与网页媒体资源托管：首期需求方案

2026-11-02，Asia/Shanghai。此版本依据用户最新澄清，取代此前“网页、音视频混排专辑 / 独立音视频作品页”的理解。用户需要的是网页发布时，将图片、视频和音频作为独立素材上传，再把网页中的引用改为返回的资源地址。专辑只组织网页。

本轮仍为本地完整交互预览，源码分支 `codex/albums-media-preview`，未生产接入、迁移、上线或发布网球内容。预览入口与边界见 `next/albums-media/README.md`。

## 1. 两项独立功能

**专辑**：将相关网页整理成有封面、固定网址和内容顺序的集合，分享一个链接即可浏览全部网页。同一网页可加入多个专辑，不复制正文或依赖资源。

**网页依赖托管**：发布网页时，AI找出其中图片、视频和音频，分别上传或复用已有素材，再替换网页引用。播放器、时间轴、声音节点和其他交互留在原网页内；媒体资源不是新增作品类型，不进入专辑目录。

首例「挥动网球测试」仅加入《网球位置与击球声·试标结果》网页。专辑和网页正式范围都明确为 unlisted，不默认加入其他网球报告、竞品研究、完整原片或额外声音文件。现有标注页实际依赖65张图片、两段含声视频；本地解码WAV只用于技术验收样例，不作为正式发布内容。

## 2. 专辑与个人主页

- 专辑有独立身份、标题、可选简介、封面、稳定网址、创建/更新时间和网页顺序。改名、更新或换封面不改变地址。
- 首期展示位置为「不展示 / 仅个人主页」，默认不展示。两者凭链接匿名访问；不提供同事白名单、密码、期限或DRM。
- 专辑与成员网页的listing独立。加入专辑不改变网页listing；专辑进入主页后，访客能经专辑找到其中网页，即使网页不在独立作品区展示。加入指定网页属于明确收录操作，不自动扫描并加入其他unlisted网页。
- 个人主页由本人开启，AI不能代开。主页关闭不影响已发布专辑直链访问。
- 主页布局：作者介绍/AI伙伴 → 专辑 → 共创作品 → 按原规则展示的素材。没有可展示专辑就隐藏专辑区。封面卡片宽屏3列、平板2列、手机1列，支持查看全部。
- 同一网页在同一专辑只出现一次，可加入、移出、重排；支持多专辑复用。移出或删除专辑不删除网页和资源。专辑默认跟随网页当前已发布版本。
- unlisted专辑不从公开作品的“所属专辑”、搜索、公开API或站点地图反向暴露。独立素材不反向披露隐藏专辑。
- 内容与资料仍交给AI管理。网站不新增手工上传、内容编辑、复制按钮或管理弹窗；本人登录与授权保持必要入口。

## 3. 网页发布与资源替换流程

1. **读取完整成品并检查依赖**：分析HTML中的 `src`、`source`、`srcset`、`poster`、CSS `url()`，以及脚本/JSON中实际用于播放器和图片的地址。内嵌data URI解码为原始文件；本地相对地址先解析到正确文件。动态引用需结合实际运行核验，不仅扫描HTML标签。
2. **生成资源清单**：记录原引用、类型、大小、SHA256、实际文件、预期用途和上传状态。不把工作帧、来源API缓存、凭证、整个父目录或无关资料当作依赖上传。
3. **上传或复用素材**：在已授权空间内核对同SHA原字节资源，有可用版本就复用；否则沿既有独立素材上传链路上传。网页依赖新资源明确设unlisted，避免继承空间public默认值而进入公开目录，不修改既有素材的展示范围。
4. **使用真实返回URL替换引用**：保留原件，在发布副本中修改data URI、相对路径和已确认的脚本地址映射；不猜服务URL，不通过全局乱替换改掉无关文字。视频/音频的播放器和操作代码保持原功能。
5. **依赖完整后发布网页**：资源未全部成功上传时，不发布指向缺失资源的新网页。保持原网页在失败期间可用；记录资源回执便于重试，不靠换slug创建副本。
6. **验证后加入专辑**：实际打开网页，核对图片、含声视频、独立音频、拖动、节点循环、放大、导出及跨域/沙盒行为。专辑只列网页，不为每份媒体生成作品条目或额外封面。

网页已有外部资源地址时，按用户授权保留或迁移可取得的媒体文件，不将平台页面假装成媒体直链，不擅自下载受限内容或索取他站Cookie。此前讨论的“独立外站音视频收录 / 平台播放页”退出本轮范围。

## 4. 资源、版本与清理

- 图片、视频、音频使用统一素材身份，记录URL、MIME、字节数、SHA和所属发布者。时长/编码等信息只填实际探测值，不以扩展名保证可播放。
- 页面引用应固定到资源的不可变版本。网页更新时未变化资源复用；媒体替换生成新资源版本，再更新网页引用，避免历史网页悄悄读取不同内容。
- 每份已发布网页版本保存依赖清单。应区分“一个素材被多网页引用”与“同一网页被多专辑收录”，后者不新增文件引用或重复占额。
- 素材库继续按文件管理，提供类型、大小、引用网页等信息；不增加独立音视频作品页、专辑媒体列表或平台内容发现。依赖资源不会自动公开收录。
- 删除专辑保留网页和素材；归档网页不自动删除或撤销独立素材URL。素材本身下架/删除会影响所有引用它的网页，处理前必须核对当前和保留版本的引用，不删除共用对象。
- 上传失败或废弃网页草稿可能留下未引用素材，应根据回执和引用检查清理。不能删除已被其他网页使用的资源，也不能把归档当作永久释放空间。
- 不默认扩大账号额度，不在本轮承诺256MiB等新上限。沿当前真实上传能力执行；如单文件超过现有25MiB范围，再在生产实现中完善可恢复上传与实际容量限制。仅拆HTML不代表已解决大文件上传。

## 5. 性能与质量边界

HTML中移除base64媒体后，正文下载/解析更轻，图片和音视频可按需请求，并可利用分段读取与资源缓存。完整看完所有媒体时，媒体本身仍有原来的大小；不能把拆分称为已压缩原媒体，也不宣称未经对照测量的首屏耗时改善百分比。

不自动有损转码、降分辨率或改画质凑限额。需要兼容播放副本时，先保留原件并依据授权处理；不额外生成用户未要求的音轨、字幕或转写作为正式内容。

保持合理的 `loading`、`preload`、`playsinline` 等行为，不默认自动播放或下载全部媒体。核验正确MIME、GET/HEAD、正常/尾部/越界Range、CORS、缓存与跨域Canvas/沙盒的实际功能。

本次本地样例：原内嵌HTML 64,569,740字节；替换67份资源为第二本机源的固定SHA地址后，HTML为78,941字节（约77KiB），65张图片和两段视频SHA全一致，替换过程可逆还原原相对资源版HTML。资源URL模拟已上传结果，未调用云端上传接口，不代表生产资源管线已交付。

## 6. 专辑封面与状态

专辑封面建议16:9、1600×900，最低800×450；用户上传JPG/PNG/WebP，建议≤5MiB。其他比例由AI制作裁剪副本，不拉伸、不覆盖原图。未提供时由AI生成并保存专属封面，可用程序排版或安全SVG；运行时保留失败兜底。封面用于专辑卡片、详情和分享预览，不为每段网页依赖媒体强制生成封面。

专辑支持正常、空、加载、读取失败及重试、已归档/删除状态。网页下架后目录不泄露旧摘要、图片与链接。引用资源缺失或不能播放要明确提示并保留现有可用版本，不把局部加载失败说成整个站点不可用。

“我的”始终是当前登录者自己的管理空间。未登录者可以看分享专辑；点击“我的”得到登录提示，登录后管理的是自己的内容，不能进入专辑作者后台。

## 7. Skill与工具的生产接入要求

- 专辑创建/查找/修改、加入/移出/排序、封面、独立展示位置、稳定URL及修订号检查。
- AI发布网页时默认检查图片/音视频依赖，拆出内嵌资源、按SHA复用、单独上传、替换引用、提交完整网页并保留依赖清单；减少HTML体积不改原媒体质量。
- 现有明确展示选择不重复询问；网页依赖素材不自动公开展示，更新保留原网页/专辑URL及listing。
- 明确原字节、实际服务限制、资源上传失败重试与引用安全清理规则。MCP不能读取Mac路径时用授权附件或本机CLI，不假装已上传本机文件。
- 发布后独立回读并实际验收网页内媒体。不以HTTP200、资源上传成功或缩小HTML大小代替播放和交互检查。
- 同步公共/本机双语Skill、CLI、REST/MCP协议与插件包；变更工具元数据后刷新既有连接并在新对话实际调用验收。当前只是本地预览与方案修订，尚未更新生产Skill或工具。

## 8. 当前预览与后续

预览保留多专辑布局、个人主页展示控制、访客文案等已认可部分。已移除专辑独立音视频条目、独立播放页、外站平台跳转演示和虚拟180MiB上传进度。

主样例专辑只含标注网页；网页以真实独立资源URL播放原有两段视频。额外的 `/dependency-check/` 是本地技术验收页，验证HTML `video/source`、`audio/source` 的按需加载与独立资源引用，不收录到专辑、不作为正式作品。素材库统一展示图片、视频与音频文件及引用关系。

下一步按这次澄清验收更新的本地预览；后续只有用户明确要求生产接入/上线时，再完成真实资源上传/复用/引用清单、专辑后端、全端技能与线上验收，最终发布专辑和网页。没有需要用户重复确认的概念或展示范围。
