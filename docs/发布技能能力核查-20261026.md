# 发布技能能力核查 · 2026-10-26

范围：对照现有service/mcp.mjs的20工具、worker/账号/社区/生命周期接口、remote_publish.py实际参数，核查公共Skill、本机Skill、插件Skill、在线参考、OpenAPI、下载包与版本说明。只修说明，不扩展后端能力或修改正式作品。

## 已修正的问题

1. 参考文档仍写“MCP尚未提供”、苏博仍待迁移、草稿只能联系所有者清理，且复制旧版网站入口3次；更新为当前实际能力并移除重复。
2. 旧文档把设置描述为手动编辑显示名/联系方式；现在内容与资料由AI操作，本人只在对应账号页做验证、主页授权和密钥管理。
3. CLI show被写为读取公开作品；实际是本人作品/草稿/归档。公开目录、个人主页与本人集合分开说明。
4. 统一更新图标的说法不准确：CLI publish/submit一直要求--icon；MCP publish_website可省略复用，submit_website必须icon_svg，prepare_upload要完整图标清单。8文件也包含图标/封面。
5. “更新”未充分区分完整新版包与补丁，容易丢依赖或旧摘要/标签/封面。明确仅listing和ai_partners省略沿用；其他字段及素材权限必须核对并重传意图，cover仍需图片入包。
6. 伙伴资料与作品署名容易混用：先复用已登记key、用伙伴自己的revision；model/contribution属于作品；名片登记不补旧作，false不抹除可见作品署名。历史参与必须有明确确认，不能推断。
7. 入口description没覆盖资料/伙伴；增加真实任务触发，并将MCP与CLI对照写到公共入口，本机复制参考与客户端使相对路径实际可用。
8. 补充一键8文件/32MiB、MCP JSON 3MiB及分步250文件/100MiB区别；密钥与OAuth、版本冲突、分档验收和删除结束条件明确。

## 明确标注的真实缺口

- 无普通用户metadata-only作品标题/摘要/封面/AI署名接口；有完整成品可更新同作品，缺源包不能用空HTML替换。苏博改标题和旧作署名的所有者维护不是公共工具。
- 无删除伙伴身份工具。show_on_profile=false仅取消独立展示；移除作品署名需完整作品更新。
- 无单独清理已发布作品某一废弃草稿版本的普通接口；不能为省额度删除整份正式作品。
- MCP submit_website不接收CLI的所有元数据参数，例如tags/license；不声称这些字段可用。
