# TexoPub 开发、预览与发布流程

2026-10-26 起使用本地 Git 管理代码。此前项目没有 Git 仓库，本轮先建立源码基线，再创建设计分支。

- `main`：已上线源码；改版前回退基线为 `6cf24c8`。
- `feat/community-gallery`：A方向设计与正式接入分支；正式源码 `templates/community/`，历史预览 `next/`。
- 2026-10-27 已创建公开仓库 https://github.com/ivanliyuanning/texopub，origin 为该仓库；main 及英文功能分支已推送，GitHub Actions 实际通过。源码 MIT 开源，私人原件、账号数据和凭证继续排除。新改动遵循分支开发、验收后合并；线上结果仍须独立核对。
- 凭证、构建缓存、部署产物、大型作品源与验收证据按 `.gitignore` 排除。Git 管理代码，不替代现有内容存储和项目备份；已有未纳入 Git 的本地资料不自动删除或公开。

## 日常顺序

1. 从确认的基线创建功能分支，记录任务范围。生产代码修改、迁移和 Skill 更新放在同一可审查分支；避免直接在 `main` 开发。
2. 在分支实现并做对应检查。预览尽量隔离真实数据写入；需要真实服务验收时明确测试对象与清理范围。
3. 提交可运行、可复现的完整预览，提供页面入口、已知限制和检查证据。
4. 用户明确认可后，再整合生产接口并完成必要验收；若审核对象还有实质变化，更新完整预览。
5. 用户决定合并上线后，合并已验收分支。仅合并代码不代表部署成功；部署后独立读取线上页面、接口与资源验证。
6. 记录发布提交、部署 ID、数据迁移与回退点。涉及 AI 能力时，同步公共与本机 Skill、插件包、文档及版本；工具元数据变更按 `service/README.md` 刷新连接并在新对话实测。

## 当前明确约定

用户现已认可预览，并明确授权正式接入、整体测试通过后合并上线。执行真实服务验收、迁移与部署，保存回退点；部署后独立核验线上结果，不把本地预览当作交付。

后续发布应保留当前生产版本供回退；服务数据迁移需单独考虑兼容性，不能把 Git 回退误称为已撤回数据库变化。
